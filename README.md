# Linux Monitoring v2.0 (DO4)

Комплексный проект по автоматизации системного администрирования, генерации и очистке тестовых данных, анализу серверных журналов (Nginx/Apache), мониторингу инфраструктуры и визуализации метрик в стеке **Prometheus + Node Exporter + Grafana** в рамках образовательной программы School 21.

## 🏛 Архитектурные стандарты (Chapter III)

1. **Модульность:** Сценарии не пишутся монолитными простынями. Вся логика разбита на подключаемые модули:
   ```
   01/
   ├── main.sh       # Точка входа (валидация $#, импорт, координация)
   ├── validate.sh   # Проверка типов параметров и граничных условий
   ├── generator.sh  # Алгоритмы конструирования имён
   └── create.sh     # Работа с диском, fallocate, контроль свободного места
   ```
2. **Безопасное подключение модулей:** Независимость от директории вызова через `${BASH_SOURCE[0]}`:
   ```bash
   DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
   source "$DIR/validate.sh"
   ```
3. **Безопасность диска:** Мониторинг свободного места через `df --output=avail -m /` с аварийной остановкой при остатке $\le 1024$ Мб во избежание сбоя хостовой ОС.

## 🚀 Быстрый запуск

### Запуск Part 1 (Генератор файлов):
```bash
# Синтаксис: main.sh <путь> <кол-во_папок> <буквы_папок> <кол-во_файлов> <буквы_файлов> <размер>
bash 01/main.sh /tmp/test_dir 4 az 5 az.az 3kb
```
*Результат:* Будут сгенерированы 4 вложенные папки, в каждой по 5 файлов размером 3 Кб, а пути зафиксированы в `file.log`.

### Запуск Part 2 (Засорение файловой системы):
```bash
# Синтаксис: main.sh <буквы_папок> <буквы_файлов> <размер_файла>
bash 02/main.sh az az.az 10Mb
```
*Результат:* Автономный поиск доступных каталогов, создание до 100 папок со случайным числом файлов (до 100) размером 10 Мб в каждой до остатка $\le 1$ Гб свободного места на `/`. В конце выводит время старта, окончания и длительность выполнения, а также логирует все пути в `file.log`.

### Запуск Part 3 (Очистка файловой системы):
```bash
# Синтаксис: main.sh <метод_очистки: 1, 2 или 3>
bash 03/main.sh 1   # Очистка по лог-файлу (запрашивает путь к file.log)
bash 03/main.sh 2   # Очистка по дате и времени создания (YYYY-MM-DD HH:MM)
bash 03/main.sh 3   # Очистка по маске имени (например, az_280926)
```

### Запуск Part 4 (Генератор логов Nginx):
```bash
# Запуск без параметров:
bash 04/main.sh
```
*Результат:* В каталоге `04/` создаются 5 файлов `nginx_1.log` ... `nginx_5.log` в Combined Log Format со случайным числом строк (от 100 до 1000) со строго возрастающим временем за 5 дней.

### Запуск Part 5 (Мониторинг логов Nginx через awk):
```bash
# Синтаксис: main.sh <режим: 1, 2, 3 или 4>
bash 05/main.sh 1   # Все записи, отсортированные по коду ответа (sort -k9,9n)
bash 05/main.sh 2   # Все уникальные IP, встречающиеся в записях (!seen[$1]++)
bash 05/main.sh 3   # Все запросы с ошибками (коды 4xx и 5xx)
bash 05/main.sh 4   # Все уникальные IP среди ошибочных запросов
```

#### Команды для проверки Part 5:
```bash
# 1. Проверка сортировки Режима 1 (коды ответов возрастают):
bash 05/main.sh 1 | awk '{print $9}' | head -n 10   # коды 200..
bash 05/main.sh 1 | awk '{print $9}' | tail -n 10   # коды 503..
bash 05/main.sh 1 | awk '{print $9}' | sort -C -n && echo "Strictly sorted!"

# 2. Проверка уникальности IP Режима 2 (число строк равно числу уникальных строк):
diff <(bash 05/main.sh 2) <(bash 05/main.sh 2 | sort -u) && echo "All IPs are unique!"

# 3. Проверка фильтрации ошибок Режима 3 (только коды 4xx и 5xx, без 200/201):
bash 05/main.sh 3 | awk '{print $9}' | sort -u

# 4. Проверка защитных барьеров (Guard Clauses):
bash 05/main.sh       # Ошибка: One argument. (exit 1)
bash 05/main.sh 5     # Ошибка: An argument from one to four. (exit 1)
bash 05/main.sh 1 2   # Ошибка: One argument. (exit 1)
```

### Запуск Part 6 (GoAccess):
```bash
# Синтаксис: main.sh (без аргументов)
bash 06/main.sh                      # Генерирует 06/report.html

# Способ 1: Открытие HTML-отчёта в браузере (WSL2 / Windows)
explorer.exe report.html          # Открытие в браузере хоста
# (или кликнуть по 06/report.html в проводнике VS Code)

# Способ 2: Интерактивный терминальный дашборд (TUI в консоли)
goaccess 04/*.log --log-format=COMBINED
```
*Результат:* Выполняет проверку окружения (`goaccess`, наличие логов `04/*.log`, запрет аргументов), объединяет 5 лог-файлов Nginx и компилирует интерактивный веб-дашборд `06/report.html`.

### Запуск Part 7 (Prometheus + Grafana: системный мониторинг):
```bash
# Синтаксис: main.sh (без аргументов)
bash 07/main.sh
```
*Результат:* Запускает интерактивное меню управления тестами (`07/menu.sh`) для визуализации системных метрик в реальном времени на дашборде Grafana (`07/dashboard.json`):
1. **Пункт 1:** Запуск стресс-теста CPU и RAM (`stress -c 2 -i 1 -m 1 --vm-bytes 32M -t 10s`) $\to$ всплеск графиков CPU/Memory в Grafana.
2. **Пункт 2:** Запуск теста диска через `02/main.sh az az.az 10Mb` $\to$ уменьшение свободного места на `/` и рост активности Disk I/O.
3. **Пункт 3:** Интерактивная очистка файловой системы через `03/main.sh` (по логу, дате или маске).
4. **Пункт 4:** Быстрый вывод ссылок на веб-интерфейсы Grafana (`http://192.168.56.101:3000`) и Prometheus (`http://192.168.56.101:9090`).
5. **Пункт 5:** Мгновенная проверка статусов системных демонов (`prometheus`, `prometheus-node-exporter`, `grafana-server`).
6. **Пункт 0:** Выход из меню.

*Конфигурация дашборда:* Файл `07/dashboard.json` содержит готовую сериализованную конфигурацию кастомного дашборда Grafana с 4 обязательными панелями:
* **CPU:** `100 - (avg by (instance) (irate(node_cpu_seconds_total{mode="idle"}[1m])) * 100)`
* **Available Memory:** `node_memory_MemAvailable_bytes`
* **Free Disk Space:** `node_filesystem_avail_bytes{mountpoint="/"}`
* **Disk I/O:** `irate(node_disk_read_bytes_total[1m])` / `irate(node_disk_written_bytes_total[1m])`
