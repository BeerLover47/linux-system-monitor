## 1. Архитектура скриптов и декомпозиция

По регламенту разработки (Chapter III) каждый скрипт должен быть декомпозирован: основной сценарий `main.sh` управляет потоком выполнения, а прикладная логика выносится в подключаемые модули.

### Базовый шаблон связки модулей

**`main.sh` (Точка входа и проверка окружения):**
```bash
#!/bin/bash

# 1. Проверка количества параметров
if [ $# -ne 1 ]; then
    echo "Error: Wrong number of arguments."
    exit 1
fi

# 2. Безопасное определение директории скрипта для импорта модулей
DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
source "$DIR/check.sh"

# 3. Передача управления модулю
check_arg "$1"
```

**`check.sh` (Изолированная логика):**
```bash
#!/bin/bash

check_arg() {
    # Логика обработки и проверок
    ...
}
```

## 2. Валидация входных данных

Задача валидации — строго разграничить допустимый ввод от некорректного (в частности, отличить число от текстовой строки).

### 2.1. Регулярное выражение для чисел (целые и вещественные)
```bash
^[-+]?[0-9]+([.][0-9]+)?$
```

#### Анатомия шаблона:
* `^` и `$` — **Якоря начала и конца строки.** Обязательны. Без них Bash ищет шаблон внутри строки (например, строка `test.12` будет ошибочно признана числом).
* `[-+]?` — **Опциональный знак.** Квантификатор `?` допускает 0 или 1 вхождение знака `+` или `-`.
* `[0-9]+` — **Обязательная целая часть.** Минимум одна цифра до точки.
* `([.][0-9]+)?` — **Опциональная дробная часть.** Круглые скобки связывают разделитель и цифры в единый блок, а знак `?` разрешает числу быть как целым (`42`), так и дробным (`3.14`). Точка экранируется `[.]` или `\.` (иначе в regex точка означает «любой символ»).

#### Антипаттерны валидации:
* ❌ `[[ $1 =~ ^-?[0-9]+$ && $1 =~ [.][0-9]+ ]]` — **Логический тупик.** Условие `&&` требует одновременного отсутствия точек и обязательного наличия точки. Выражение всегда вычисляется в `false`.
* ❌ `[[ $1 =~ [.][0-9]+ ]]` — **Плавающий поиск.** Отсутствие якорей приведет к ложному срабатыванию на именах файлов и версиях (`app_v1.0.tar`).

#### Матрица верификации (P2P Test Cases):
| Входные данные | Ожидаемый результат | Код (`$?`) | Назначение теста |
| :--- | :--- | :---: | :--- |
| *(без параметров)* | Сообщение об ошибке | `1` | Проверка условия `$#` |
| `arg1 arg2` | Сообщение об ошибке | `1` | Избыточные параметры |
| `42`, `-10` | Сообщение: это число | `1` | Целые положительные и отрицательные |
| `3.14`, `-0.5` | Сообщение: это число | `1` | Дробные положительные и отрицательные |
| `hello` | Печать значения | `0` | Корректный текстовый аргумент |
| `hello123` | Печать значения | `0` | Строка с цифрами (не число) |

## 3. Сбор системной информации: Сетевой стек

В *Ubuntu 24.04 LTS* утилита `ifconfig` (пакет `net-tools`) отсутствует по умолчанию. Для работы с сетью используется штатный стандарт **`iproute2` (`ip`)**.

### 3.1. Динамическое определение интерфейса
Имя активного сетевого интерфейса варьируется от системы к системе (`eth0`, `enp0s3`, `ens33`, `wlan0`). Имя определяется динамически по маршруту по умолчанию:
```bash
INTERFACE=$(ip route | awk '/default/ {print $5}')
GATEWAY=$(ip route | awk '/default/ {print $3}')
```
*В выводе `ip route` поле `$5` содержит имя интерфейса, а поле `$3` — IP шлюза.*

### 3.2. Определение маски подсети (MASK)
Утилита `ip` возвращает маску в формате префикса CIDR (например, `/24`). Решение состоит из двух шагов:

#### Шаг 1: Извлечение числа бит (CIDR)
```bash
MASK_CIDR=$(ip -o -4 addr show "$INTERFACE" | awk -F'[/ ]+' '{print $5}')
```
*Флаг `-F'[/ ]+'` объявляет и пробелы, и слэш разделителями полей. Это позволяет извлечь число после слэша в одну команду без использования `cut`.*

#### Шаг 2: Преобразование CIDR в формат `xxx.xxx.xxx.xxx`
* **Способ А (Python `ipaddress` — максимальная надёжность):**
  ```bash
  MASK=$(python3 -c "import ipaddress; print(ipaddress.IPv4Network('0.0.0.0/$MASK_CIDR').netmask)")
  ```
  *Обоснование: стандартный встроенный модуль Python 3 исключает математические ошибки при расчете нестандартных масок подсетей.*

* **Способ Б (Чистый Bash — максимальное быстродействие):**
  ```bash
  MASK=$(val=$(( 0xFFFFFFFF << (32 - MASK_CIDR) )); echo "$(( (val >> 24) & 255 )).$(( (val >> 16) & 255 )).$(( (val >> 8) & 255 )).$(( val & 255 ))")
  ```
  *Обоснование: расчет выполняется мгновенно встроенными средствами оболочки без создания дополнительных процессов.*

## 4. Чеклист оформления и защиты (P2P Defense)

| Пункт проверки | Требование задания | Верно | Ошибка | Причина строгости |
| :--- | :--- | :--- | :--- | :--- |
| **Память** | `RAM_TOTAL`, `RAM_USED`, `RAM_FREE` | `3.125 GB` | `3.125 Gb` | Строчная `b` означает биты, прописная `B` — байты. |
| **Диск** | `SPACE_ROOT` | `254.25 MB` | Другой масштаб | Требуется размер в Мб с точностью 2 знака (`%.2f MB`). |
| **Файл статуса** | Имя `DD_MM_YY_HH_MM_SS.status` | `%d_%m_%y_%H_%M_%S.status` | Использование `%Y` | В ТЗ указан 2-значный год (`%y`), а не 4-значный (`%Y`). |
| **Диалог с пользователем** | Сохранение `Y/N` | Однократный опрос | Цикличный запрос на любой ввод | ТЗ: «все прочие ответы считаются отрицательными». |

## 5. Исследование файловой системы

Подводные камни при парсинге списков файлов и папок в Linux:

### 5.1. Безопасное извлечение расширения файла
* **Антипаттерн:** Использовать `${path##*.}` прямо на полном пути.
  * *В чём риск:* Если у файла нет расширения, но в пути есть скрытая папка с точкой (например, `/home/user/.gemini/bin/agy`), в качестве расширения вернется остаток пути: `gemini/bin/agy`.
* **Решение:** Сначала изолировать чистое имя файла через `basename`:
  ```bash
  filename=$(basename "$path")
  if [[ "$filename" == *.* ]]; then
      ext="${filename##*.}"
  else
      ext="no extension"
  fi
  ```

### 5.2. Форматирование размерностей без глобального `sed`
* **Антипаттерн:** `sed -e 's/K/KB/' -e 's/M/MB/' -e 's/G/GB/'` над строкой `du`.
  * *В чём риск:* Замена происходит по всей строке. Папка `Music` исказится в `MBusic`, `Games` — в `GBames`, а `Katalog` — в `KBatalog`.
* **Решение:** Добавлять литеру `B` при выводе переменной в цикле `read`:
  ```bash
  while read -r size path; do
      echo "$i - $path, ${size}B"
      i=$((i + 1))
  done
  ```

### 5.3. Изоляция типа файла через `file -b`
* **Антипаттерн:** `find ... -exec file {} + | grep -c "text"`.
  * *В чём риск:* Поиск ведется по всей строке. Любой файл, содержащий `text` в имени (например, `context.png`), посчитается текстовым файлом.
* **Решение:** Флаг `-b` (brief) исключает имя файла из вывода, оставляя только тип:
  ```bash
  text=$(find "$1" -type f -exec file -b {} + 2>/dev/null | grep -c "text")
  ```
