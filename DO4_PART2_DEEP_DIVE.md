## 1. Паспорт задания и требования Школы 21

Скрипт запускается с **3 позиционными параметрами**:
```bash
./main.sh az az.az 10Mb
```

| № | Параметр | Ограничения и тип | Назначение в алгоритме |
|---|---|---|---|
| **1** | Буквы папок | Английский алфавит, $1 \le \text{длина} \le 7$ | Набор символов для генерации имён каталогов |
| **2** | Буквы файла | Формат `name.ext` (имя $\le 7$ букв, расширение $\le 3$ буквы) | Набор символов для имени и расширения файлов |
| **3** | Размер файлов | От $1$ до $100$ с суффиксом `Mb` / `MB` (например: `10Mb`, `100MB`) | Вес каждого файла при аллокации |

### Ключевые отличия Part 2 от Part 1:
1. **Минимальная длина:** буквенная часть имени папки и файла обязана быть **не менее 5 знаков** (в Part 1 было $\ge 4$).
2. **Размер файлов:** измеряется строго в **мегабайтах** (`Mb` / `MB`), до $100\text{ Mb}$ (в Part 1 было в `kb`).
3. **Автономный выбор мест записи:** базовый путь не передаётся пользователем. Скрипт самостоятельно ищет доступные для записи каталоги по всей системе, исключая бинарные и псевдофайловые папки ядра (`bin`, `sbin`, `proc`, `sys`, `dev`, `run`).
4. **Масштаб генерации:** создаётся **до 100 папок** в случайно выбранных каталогах. В каждой созданной папке генерируется **случайное число файлов** (от 1 до 100).
5. **Замер времени выполнения:** фиксируется время старта, время окончания и общая длительность работы в секундах. Данные выводятся на экран и добавляются в конец лог-файла.
6. **Остановка по свободному месту:** работа прекращается, как только свободное место на корневом разделе `/` достигает порога $\le 1$ Гб.

### Инварианты выполнения:
- **Сохранение алфавитного порядка:** `az` $\to$ `aaaaz`, `aazzz`, но ни в коем случае не `zaaaa`.
- **Полнота символов:** каждый переданный символ алфавита присутствует в сгенерированном имени минимум один раз.
- **Суффикс даты:** к имени каждой папки и файла прикрепляется дата запуска в формате `_DDMMYY`.
- **Журналирование:** каждая операция фиксируется в `file.log` (полный путь, дата, для файлов — размер).

## 3. Анатомический разбор `main.sh` (Оркестратор и таймер)

```bash
#!/bin/bash

DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
source "$DIR/validate.sh"
source "$DIR/generator.sh"
source "$DIR/create.sh"

validate_args "$@"
start_time="$(date +'%Y-%m-%d %H:%M:%S')"
start_sec=$(date +%s)

creation "$1" "$2" "$3"

end_time="$(date +'%Y-%m-%d %H:%M:%S')"
end_sec=$(date +%s)
duration=$(awk -v start="$start_sec" -v end="$end_sec" 'BEGIN { printf "%.2f\n", end - start}')
log_file="$(pwd)/file.log"
{
  echo "START TIME: $start_time"
  echo "END TIME: $end_time"
  echo "Script execution time: $duration"
} | tee -a "$log_file"
```

### Построчный анализ `main.sh`:
- **Строки 3–6:** каноническое вычисление абсолютного пути к скрипту через `${BASH_SOURCE[0]}`. Гарантирует корректное подключение соседних модулей независимо от текущего рабочего каталога при запуске.
- **Строка 8 (`validate_args "$@"`):** запуск валидации переданных аргументов. В случае несоответствия скрипт прерывается с кодом `1`.
- **Строки 9–10:** фиксация времени начала. `start_time` сохраняет читаемый формат для логов (`%Y-%m-%d %H:%M:%S`), а `start_sec` — Unix Timestamp в секундах для арифметики.
- **Строка 12 (`creation "$1" "$2" "$3"`):** запуск основного цикла создания файловой структуры.
- **Строки 14–16:** фиксация времени завершения и расчёт времени работы. Утилита `awk` вычисляет разницу с точностью до двух знаков после запятой, избегая ограничений целочисленной арифметики Bash.
- **Строки 17–22:** группировка строк в блок `{ ... }` и атомарная передача через пайп в `tee -a "$log_file"`. Данные одновременно выводятся в стандартный вывод терминала (`stdout`) и дописываются в конец журнала.

## 4. Анатомический разбор `validate.sh` (Защитные барьеры)

```bash
#!/bin/bash

validate_args() {
  if [ "$#" -ne 3 ]; then
    echo "Error: script accepts 3 parameters: folder_letters file_letters size" >&2
    exit 1
  fi

  local folder_letters="$1"
  local file_letters="$2"
  local file_size="$3"

  if [[ ! "$folder_letters" =~ ^[a-zA-Z]{1,7}$ ]]; then
    echo "Error: folder letters must contain 1-7 English letters" >&2
    exit 1
  fi

  if [[ ! "$file_letters" =~ ^[a-zA-Z]{1,7}\.[a-zA-Z]{1,3}$ ]]; then
    echo "Error: file format must be letters.ext (1-7 letters name, 1-3 letters ext)" >&2
    exit 1
  fi

  if [[ ! "$file_size" =~ ^([1-9][0-9]?|100)[mM][bB]$ ]]; then
    echo "Error: file size must be between 1Mb and 100Mb" >&2
    exit 1
  fi
}
```

### Построчный анализ `validate.sh`:
- **Проверка количества (`$# -ne 3`):** гарантирует передачу строго трёх аргументов. Все ошибки пишутся строго в поток `stderr` (`>&2`).
- **Регулярное выражение папок (`^[a-zA-Z]{1,7}$`):** допускает только латинские буквы длиной от 1 до 7 символов без цифр и спецсимволов.
- **Регулярное выражение файлов (`^[a-zA-Z]{1,7}\.[a-zA-Z]{1,3}$`):** проверяет наличие обязательной точки-разделителя, имя до 7 латинских букв и расширение от 1 до 3 букв.
- **Регулярное выражение размера (`^([1-9][0-9]?|100)[mM][bB]$`):**
  - `[1-9]` — числа от 1 до 9.
  - `[1-9][0-9]` — двузначные числа от 10 до 99.
  - `100` — верхняя допустимая граница.
  - `[mM][bB]` — регистронезависимый суффикс `Mb`, `MB`, `mb`, `mB`. Числа вида `0Mb`, `101Mb`, `05Mb` отсекаются.

## 5. Анатомический разбор `generator.sh` (Алгоритмы именования)

```bash
#!/bin/bash

generate_folder_name() {
  local letters="$1"
  local index="$2"
  local date_suffix="$(date +'%d%m%y')"
  local first_char="${letters:0:1}"
  local rest_chars="${letters:1}"
  local pad_len=$(( 5 - ${#letters} ))
  if [ "$pad_len" -lt 0 ]; then
    pad_len=0
  fi
  local extra_len=$(( pad_len + index ))
  local padding=$(printf "%${extra_len}s" | tr ' ' "$first_char")
  echo "${padding}${rest_chars}_${date_suffix}"
}

generate_file_name() {
  local letters="$1"
  local ext="$2"
  local index="$3"
  local base_name=$(generate_folder_name "$letters" "$index")
  local name_no_date="${base_name%_*}"
  local date_suffix="${base_name##*_}"
  echo "${name_no_date}_${date_suffix}.${ext}"
}
```

### Построчный анализ `generator.sh`:
- **Расчёт дополнения до 5 символов:**
  `local pad_len=$(( 5 - ${#letters} ))`  
  В отличие от Part 1 (где требовалось $\ge 4$ знаков), в Part 2 минимальный порог поднят до 5. Если длина исходного набора букв меньше 5, недостающая длина компенсируется размножением первой буквы.
- **Смещение по индексу (`extra_len=$(( pad_len + index ))`):**
  Гарантирует уникальность каждого последующего сгенерированного имени за счёт инкрементального удлинения ведущего символа при каждой итерации цикла.
- **Генерация строки повторов без циклов:**
  `printf "%${extra_len}s" | tr ' ' "$first_char"`  
  Высокопроизводительный трюк POSIX: утилита `printf` создаёт строку пробелов заданной длины, а `tr` мгновенно заменяет их на нужный символ.
- **Декомпозиция имени файла через Parameter Expansion:**
  - `${base_name%_*}` отсекает дату с конца, получая расширенное базовое имя.
  - `${base_name##*_}` извлекает чистый суффикс даты.
  - Итоговое имя файла формируется в виде `${name_no_date}_${date_suffix}.${ext}`.

## 6. Анатомический разбор `create.sh` (Системные вызовы, сканирование и аллокация)

### Функция `check_free_space`
```bash
check_free_space() {
  local free_space=$(df -h --output=avail / | tail -n 1 |
  awk '/G/{print int($1*1024)} /M/{print int($1)} /K/{print 0}')

  if [ "$free_space" -le 1024 ]; then
    echo "Attention: there is less than 1GB of space left on the disk (${free_space} MB left)" >&2
    return 1
  fi
  return 0
}
```
- Использование `--output=avail` предотвращает смещение колонок при длинных именах устройств в выводе `df`.
- Обработка единиц измерения через `awk`: значения в гигабайтах (`G`) конвертируются в мегабайты умножением на 1024, мегабайты (`M`) берутся напрямую, килобайты (`K`) приводятся к нулю.
- Если свободного места $\le 1024$ Мб (1 Гб), функция выводит предупреждение в `stderr` и возвращает код `1`.

### Функция `get_target_dirs`
```bash
get_target_dirs() {
  find / -maxdepth 4 -type d -writable 2>/dev/null |
  grep -vE '/(bin|sbin|sys|dev|proc|run|mnt|media)(\/|$)'
}
```
- Ограничение глубины поиска `-maxdepth 4` защищает скрипт от многоминутного обхода глубоких структур файловой системы.
- Фильтрация через `grep -vE` отсекает псевдофайловые системы ядра (`proc`, `sys`, `dev`, `run`), системные бинарные каталоги (`bin`, `sbin`), а также точки внешнего монтирования (`mnt`, `media`). В средах WSL2 и VirtualBox это критически важно: это предотвращает случайное засорение реальных дисков хоста (C:, D:, E:) и предотвращает сбои драйверов `9p`/`drvfs`/`vboxsf`.
- Перенаправление `2>/dev/null` подавляет сообщения об ошибках доступа к каталогам `Permission denied`.

### Функция `create_files_in_folder`
```bash
create_files_in_folder() {
  local folder_path="$1"
  local file_letters="$2"
  local file_ext="$3"
  local size_num="$4"
  local size_raw="$5"
  local log_file="$6"
  local count=$(( RANDOM % 100 + 1 ))
  local j
  for (( j=1; j<=count; j++)); do
    if ! check_free_space; then
      return 1
    fi
    local file_name=$(generate_file_name "$file_letters" "$file_ext" "$j")
    local file_path="$folder_path/$file_name"
    fallocate -l "${size_num}M" "$file_path" 2>/dev/null || truncate -s "${size_num}M" "$file_path"
    echo "$file_path $(date '+%Y-%m-%d %H:%M:%S') $size_raw" >> "$log_file"
  done
}
```
- Число файлов определяется случайно: `$(( RANDOM % 100 + 1 ))` (диапазон от 1 до 100).
- Проверка диска `check_free_space` выполняется **перед созданием каждого отдельного файла**. Если порог в 1 Гб превышен, создание немедленно прерывается с возвратом кода ошибки `1`.
- Аллокация выполняется системным вызовом через утилиту `fallocate -l "${size_num}M"`. В случае работы на файловой системе без поддержки `fallocate(2)` предусмотрена отказоустойчивая связка (fallback) через `truncate -s "${size_num}M"`.
- Каждая запись добавляется в лог в формате: `полный_путь дата_создания размер`.

### Функция `creation`
```bash
creation() {
  local folder_letters="$1"  
  local file_chars="$2"
  local file_size="$3"
  local log_file="$(pwd)/file.log"

  local file_name_letters=${file_chars%.*}
  local file_ext=${file_chars#*.}
  local size_mb=${file_size%[mM][bB]}

  local target_dirs=()
  mapfile -t target_dirs < <(get_target_dirs)
  if [ "${#target_dirs[@]}" -eq 0 ]; then
    echo "Error: No directories found" >&2
    return 1
  fi

  local i
  for (( i=1; i<=100; i++ )); do
    if ! check_free_space; then
      return 1
    fi
    local random_dirs="${target_dirs[RANDOM % ${#target_dirs[@]}]}"
    local folder_name=$(generate_folder_name "$folder_letters" "$i")
    local folder_path="$random_dirs/$folder_name"
    mkdir -p "$folder_path"
    echo "$folder_path $(date '+%Y-%m-%d %H:%M:%S')" >> "$log_file"
    if ! create_files_in_folder "$folder_path" "$file_name_letters" "$file_ext" "$size_mb" "$file_size" "$log_file"; then
      return 1
    fi
  done
}
```
- Чтение списка целевых директорий в массив выполняется через встроенную команду `mapfile -t` с Process Substitution `< <(...)`.
- Проверяется краевой случай: если доступных директорий не найдено, выводится ошибка и скрипт завершается с кодом `1`.
- Внешний цикл создаёт до 100 каталогов. Для каждой папки случайным образом выбирается базовая директория: `${target_dirs[RANDOM % ${#target_dirs[@]}]}`.
- Директория создаётся через `mkdir -p`, фиксируется в логе, после чего вызывается функция наполнения файлами `create_files_in_folder`. При возврате `1` из-за нехватки места внешний цикл корректно завершает работу.

## 7. Системные грабли и ловушки ядра Linux

### 1. Зависание `find /` и псевдофайловые системы ядра
Поиск без ограничения глубины или исключения `/proc` приводит к бесконечному зависанию. В `/proc` содержатся динамические структуры процессов (`/proc/$PID/cwd` и `/proc/$PID/fd`), которые образуют циклические ссылки. Ограничение `-maxdepth 4` и исключение системных точек монтирования через `grep -vE` решает проблему, сокращая время поиска с минут до 0.05 секунды.

### 2. Безопасное чтение вывода в массив через `mapfile`
Конструкция вида `target_dirs=($(find ...))` страдает от Word Splitting — любые папки с пробелами в именах будут разорваны на несколько элементов. Встроенная команда Bash `mapfile -t` (или `readarray -t`) читает строки строго построчно, безопасно сохраняя пробелы.

### 3. Разница между `local` и синтаксисом `(( ... ))`
В Bash конструкция `(( ... ))` является арифметическим контекстом, где допускаются только числовые выражения и операторы (`+`, `-`, `=`, `++`). Команда `local` — это встроенная служебная команда объявления переменных шелла. Попытка написать:
```bash
for (( local i=1; i<=100; i++ )); do  # ОШИБКА СИНТАКСИСА!
```
приведёт к немедленной ошибке парсинга Bash. Переменная обязана быть объявлена заранее: `local i; for (( i=1; i<=100; i++ )); do`.

### 4. Скорость `fallocate` при генерации десятков гигабайт
В ходе реального теста скрипт сгенерировал 100 папок и 5454 файла по 10 Мб (суммарно **~54.5 Гб данных**).
- Использование классического `dd if=/dev/zero of=...` заняло бы более 10–15 минут из-за непрерывных физических операций записи нулей в блоки диска.
- Системный вызов `fallocate` (через вызов `fallocate(2)`) аллоцирует метаданные экстентов в файловой системе ext4 за доли миллисекунды без реальной записи нулей. В результате 54.5 Гб были созданы всего за **133 секунды** (2 минуты 13 секунд).

### 5. Ошибка `fallocate failed: Operation not supported` в виртуальных окружениях (WSL2 / VirtualBox)
Системный вызов `fallocate(2)` аппаратно поддерживается нативными файловыми системами Linux (`ext4`, `xfs`, `btrfs`). При запуске в средах виртуализации с монтированием хостовых дисков (драйверы `drvfs`/`9p` в WSL2 для дисков `/mnt/c`, `/mnt/d` или `vboxsf` в VirtualBox) вызов `fallocate` падает с ошибкой ядра `EOPNOTSUPP` (`Operation not supported`).
**Архитектурное решение:**
1. Исключать каталоги точек внешнего монтирования `/mnt` и `/media` в `get_target_dirs`. Это гарантирует, что скрипт не выйдет за пределы корневого раздела `/` и не затронет диски хоста.
2. Использовать отказоустойчивый fallback: `fallocate -l "${size_num}M" "$file_path" 2>/dev/null || truncate -s "${size_num}M" "$file_path"`. Если системный вызов не поддерживается драйвером файловой системы, утилита `truncate` мгновенно создаёт разреженный (sparse) файл требуемого размера без сбоев.
