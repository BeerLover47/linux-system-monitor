# Часть I. Фундаментальные концепции Bash

## 1. Конструкция `case ... in ... esac`

Конструкция `case` в Bash — это мощный оператор множественного ветвления (аналог `switch-case` в языках C, Java, Go), который проверяет соответствие строки заданным **шаблонам (patterns / globbing)**.

### 1.1. Базовый синтаксис
```bash
case "$variable" in
    pattern1)
        # команды, если $variable совпало с pattern1
        ;;
    pattern2 | pattern3)
        # команды, если $variable совпало с pattern2 ИЛИ pattern3
        ;;
    *)
        # дефолтная ветка (если ни один шаблон выше не подошел)
        ;;
esac
```

### 1.2. Анатомия синтаксических элементов
* `case "$variable" in` — объявление проверяемого значения. Переменную **всегда рекомендуется кавычить**, чтобы пустая строка или пробелы не вызвали синтаксическую ошибку (`syntax error near unexpected token in`).
* `pattern)` — шаблон поиска, закрывающийся круглой скобкой `)`. Открывающая скобка `(` является опциональной (`(pattern)`).
* `|` — логическое «ИЛИ» внутри шаблона (например, `[Yy] | yes | YES)`).
* `;;` — обязательный терминатор ветки (аналог `break;` в C). Означает: «завершить выполнение всего оператора `case`».
* `*)` — шаблон-джокер (wildcard). Ловит абсолютно любую строку. Всегда помещается в самом конце как ветка по умолчанию (`default`).
* `esac` — слово `case` задом наперёд, обозначающее конец блока.

### 1.3. Специальные терминаторы веток в Bash (продвинутый уровень)
Помимо стандартного `;;`, Bash поддерживает два редких, но полезных оператора:
1. `;&` (fallthrough) — выполняет команды текущей ветки и **проваливается** в тело следующей ветки без проверки её шаблона (аналог отсутствия `break` в C).
2. `;;&` (test next) — выполняет команды текущей ветки и продолжает проверку **следующих шаблонов** (позволяет выполнить несколько веток, если строка подходит под несколько условий).

### 1.4. Шаблоны подстановок (Globbing в `case`)
В отличие от языков вроде C, где `switch` работает только с константами, в Bash шаблоны `case` поддерживают полноразмерный Shell Globbing:
* `*` — любое количество любых символов (включая 0).
* `?` — ровно один любой символ.
* `[...]` — любой из перечисленных символов (например, `[0-9]`, `[A-Za-z]`, `[Yy]`).
* `[!...]` — отрицание: любой символ, кроме указанных.

### 1.5. Примеры из нашего проекта
1. **Обработка ответа пользователя в `02/answer.sh`:**
   ```bash
   case "$answer" in
       [Yy]*) # Сработает на Y, y, yes, Yeah и т.д.
           ...
           ;;
       [Nn]*) # Сработает на N, n, no, nope и т.д.
           ...
           ;;
       *)     # Все остальные символы
           ...
           ;;
   esac
   ```
2. **Преобразование кодов цветов в `03/colors.sh` и `04/colors.sh`:**
   ```bash
   case "$1" in
       1) echo "\033[47m" ;; # Белый
       2) echo "\033[41m" ;; # Красный
       3) echo "\033[42m" ;; # Зеленый
       4) echo "\033[44m" ;; # Синий
       5) echo "\033[45m" ;; # Фиолетовый
       6) echo "\033[40m" ;; # Черный
   esac
   ```

## 2. Циклы в Bash (`while`, `for`, `until`)

Циклы используются для повторения инструкций. В Bash существуют три вида циклов: `for`, `while` и `until`.

### 2.1. Цикл `while`
Выполняет тело цикла до тех пор, пока команда в условии возвращает **код завершения 0 (`true`)**.

#### А. Бесконечный цикл (интерактивный диалог)
Используется в `02/answer.sh`:
```bash
while true; do
    read -r -p "Write data to a file? (y/n): " answer
    case "$answer" in
        [Yy]*) ... ; break ;;
        [Nn]*) ... ; break ;;
        *) echo "Invalid input" ;;
    esac
done
```
*Команда `true` — это встроенная утилита Bash, которая всегда завершается с кодом 0.*

#### Б. Потоковое чтение вывода команд (`while read`)
Используется в `05/dirs.sh` и `05/exac.sh`:
```bash
du -h "$1" | sort -rh | head -5 | while read -r size path; do
    echo "$size -> $path"
done
```
* **Как работает `read`:** Разделяет входящую строку по переменной разделителя `IFS` (по умолчанию пробел/табуляция). Первое слово отправляется в переменную `size`, а **весь оставшийся остаток строки** — в переменную `path`.
* **Флаг `-r`:** Запрещает интерпретировать символ обратного слэша `\` как экранирование (критично для путей к файлам, где могут быть обратные слэши или спецсимволы).

> ⚠️ **Критическая ловушка Subshell (Подоболочка):**
> Когда цикл соединяется через pipe (`command | while read ...`), Bash запускает весь цикл `while` в **дочернем процессе (subshell)**.
> Любые переменные, измененные внутри такого цикла, **исчезнут** после его завершения!
> *Пример:*
> ```bash
> count=0
> cat file.txt | while read line; do count=$((count + 1)); done
> echo $count # Выведет 0! Потому что count менялся в подоболочке!
> ```
> *Как избежать:* Использовать Process Substitution (подстановку процессов):
> ```bash
> while read line; do count=$((count + 1)); done < <(cat file.txt)
> echo $count # Выведет реальное число строк!
> ```

---

### 2.2. Цикл `for`
Используется для обхода заранее известного набора элементов.

#### А. Итерация по списку аргументов скрипта (`$@`)
Используется в `03/main.sh` для проверки всех 4 аргументов:
```bash
for arg in "$@"; do
    if ! [[ "$arg" =~ ^[1-6]$ ]]; then
        echo "Error: Arguments must be strictly from 1 to 6."
        exit 1
    fi
done
```
* `$@` — массив всех переданных позиционных параметров (`$1`, `$2`, `$3`, `$4`).
* Кавычки `"$@"` обязательны: они сохраняют аргументы с пробелами как единые элементы.

#### Б. Цикл в стиле языка C
Используется для числовых счетчиков с шагом:
```bash
for (( i = 1; i <= 10; i++ )); do
    echo "Элемент номер: $i"
done
```

---

### 2.3. Цикл `until`
Прямая противоположность `while`: выполняет тело цикла до тех пор, пока условие **ложно (код != 0)**, и останавливается, как только условие станет истинным.
```bash
count=1
until [ $count -gt 5 ]; do
    echo "Count = $count"
    count=$((count + 1))
done
```

---

### 2.4. Управление циклами: `break` и `continue`
* `break` — немедленно прерывает выполнение текущего цикла.
* `break N` — прерывает $N$ уровней вложенных циклов.
* `continue` — пропускает остаток текущей итерации и переходит к следующей.
* `continue N` — переходит на следующую итерацию внешнего цикла $N$-го уровня.

## 3. Регулярные выражения в Bash (`=~`)

Оператор `=~` доступен внутри двойных квадратных скобок `[[ ... ]]` и выполняет сопоставление строки с регулярным выражением **POSIX ERE (Extended Regular Expressions)**.

### 3.1. Таблица базовых спецсимволов и квантификаторов

| Символ | Название | Назначение в ERE | Пример совпадения |
| :---: | :--- | :--- | :--- |
| `^` | Якорь начала | Начало строки | `^abc` совпадет с `abcdef`, но не с `zabc` |
| `$` | Якорь конца | Конец строки | `xyz$` совпадет с `abcxyz`, но не с `xyza` |
| `.` | Точка | Ровно один любой символ | `a.c` совпадет с `abc`, `a-c`, `a9c` |
| `[.]` или `\.` | Экранированная точка | Буквальный символ точки | `3\.14` совпадет только с `3.14` |
| `*` | Звезда Клини | 0 или более повторений | `ab*c` совпадет с `ac`, `abc`, `abbc` |
| `+` | Плюс | 1 или более повторений | `ab+c` совпадет с `abc`, `abbc`, но не `ac` |
| `?` | Знак вопроса | 0 или 1 повторение (опциональность) | `ab?c` совпадет с `ac` или `abc` |
| `[0-9]` | Символьный класс | Любая цифра от 0 до 9 | Совпадет с любым одиночным числом |
| `( ... )` | Группа | Объединяет последовательность в блок | `(ab)+` совпадет с `ab`, `abab`, `ababab` |
| `\|` | Чередование | Логическое ИЛИ внутри regex | `cat\|dog` совпадет с `cat` или `dog` |

---

### 3.2. Детальный разбор регулярок из нашего проекта

#### Паттерн 1: Проверка числа со знаком и дробной частью (`01/check.sh`)
```bash
^[-+]?[0-9]+([.][0-9]+)?$
```
Разложим по шагам:
1. `^` — совпадение должно начинаться строго с первого символа.
2. `[-+]?` — знак числа. Символы `-` или `+` могут встретиться 0 или 1 раз.
3. `[0-9]+` — целая часть числа. Обязана содержать минимум 1 цифру.
4. `(` — начало опциональной группы.
5. `[.]` — символ разделителя (точка).
6. `[0-9]+` — дробная часть. Если точка указана, за ней обязана следовать минимум одна цифра (число `3.` будет отсеяно).
7. `)?` — закрытие группы. Знак `?` делает всю связку «точка + цифры» опциональной (допускаются и целые, и дробные).
8. `$` — совпадение должно заканчиваться последним символом строки.

#### Паттерн 2: Проверка диапазона цветов 1–6 (`03/main.sh`, `04/config.sh`)
```bash
^[1-6]$
```
* `^` и `$` гарантируют, что в аргументе находится **ровно один символ**.
* `[1-6]` разрешает только цифры `1, 2, 3, 4, 5, 6`. Любые значения `0`, `7`, `12` или `red` будут отвергнуты.

#### Паттерн 3: Проверка завершающего слэша в пути (`05/main.sh`)
```bash
/$
```
* Проверяет, заканчивается ли переданный путь символом косой черты `/`. Путь `/var/log` проверку не пройдет, а `/var/log/` — пройдет.

---

### 3.3. Что ещё можно было применить (Альтернативы)

1. **Поддержка запятой как разделителя дробной части:**
   В русскоязычной локали десятичным разделителем часто выступает запятая (`3,14`):
   ```bash
   ^[-+]?[0-9]+([.,][0-9]+)?$
   ```
2. **Числа без целой части (начинающиеся с точки):**
   В математике допустимы записи вида `.5` или `-.25`:
   ```bash
   ^[-+]?([0-9]+(\.[0-9]+)?|\.[0-9]+)$
   ```
3. **Проверка через утилиты без regex (числовая арифметика):**
   Проверка на целое число без регулярок:
   ```bash
   if [ "$1" -eq "$1" ] 2>/dev/null; then
       echo "Это целое число"
   fi
   ```
   *Команда `test` (`[`) вернет ошибку, если операнд не является числом, а `2>/dev/null` заглушит системное сообщение.*

## 4. Параметрические подстановки (Parameter Expansion)

Встроенный механизм работы со строками в Bash — один из самых производительных инструментов системного администратора. Он выполняет манипуляции прямо в оперативной памяти процесса оболочки без порождения дочерних процессов (`cut`, `awk`, `sed`), что в циклических операциях ускоряет работу скрипта в десятки раз.

### Сводная таблица параметров:

| Конструкция | Назначение | Пример (`var="report_v1.tar.gz"`) | Результат |
| :--- | :--- | :--- | :--- |
| `${#var}` | Длина строки | `${#var}` | `16` |
| `${var:-default}` | Подставить значение, если переменная пуста или не объявлена | `${empty:-"fallback"}` | `"fallback"` |
| `${var:=default}` | Присвоить переменной значение, если она пуста | `${empty:="fallback"}` | `empty="fallback"` |
| `${var:+alternate}` | Подставить значение, только если переменная **задана** | `${var:+"active"}` | `"active"` |
| `${var:offset:length}` | Срез подстроки от позиции `offset` длиной `length` | `${var:0:6}` | `"report"` |
| `${var#pattern}` | Удалить **кратчайший** префикс от начала строки | `${var#*_}` | `"v1.tar.gz"` |
| `${var##pattern}` | Удалить **длиннейший** префикс от начала строки | `${var##*.}` | `"gz"` (расширение!) |
| `${var%pattern}` | Удалить **кратчайший** суффикс от конца строки | `${var%.*}` | `"report_v1.tar"` |
| `${var%%pattern}` | Удалить **длиннейший** суффикс от конца строки | `${var%%.*}` | `"report_v1"` |
| `${var/pattern/repl}` | Заменить первое совпадение подстроки | `${var/tar/zip}` | `"report_v1.zip.gz"` |
| `${var//pattern/repl}`| Заменить все совпадения подстроки | `${var//./_}` | `"report_v1_tar_gz"` |
| `${var^^}` | Перевести всю строку в ВЕРХНИЙ регистр | `${var^^}` | `"REPORT_V1.TAR.GZ"` |
| `${var,,}` | Перевести всю строку в нижний регистр | `${VAR,,}` | `"report_v1.tar.gz"` |

### Практическое применение из проекта:
* В `05/exac.sh`: извлечение расширения файла через `${path##*.}`.
* В `05/dirs.sh`: вместо конвейера `sed -e 's/K/KB/'` можно безопасно делать `${size}B` прямо в переменной цикла.

## 5. Дескрипторы ввода-вывода и перенаправление потоков (I/O Redirection)

В Linux всё есть файл, и каждый процесс при старте получает три открытых стандартных потока:
* `0` — **`stdin`** (стандартный ввод, клавиатура).
* `1` — **`stdout`** (стандартный вывод, экран).
* `2` — **`stderr`** (стандартный вывод ошибок, экран).

### Способы перенаправления:
* `> file` — перезаписать stdout команды в файл (сокращение от `1> file`).
* `>> file` — дописать stdout в конец файла без перезаписи.
* `2> file` — перенаправить только поток ошибок.
  * *Пример из проекта:* `2>/dev/null` — отправляет любые ошибки в системную «чёрную дыру», гарантируя чистоту вывода.
* `2>&1` — перенаправить `stderr` в дескриптор `stdout`.
* `&> file` — современный синтаксис Bash: перенаправить и stdout, и stderr одновременно в один файл.
* `< file` — передать содержимое файла на вход команды.
* `<<< "$string"` (**Here-String**) — передать строковую переменную в stdin команды без вызова `echo ... |`:
  ```bash
  grep "Error" <<< "$log_line"
  ```
* `< <(command)` (**Process Substitution**) — подстановка процесса. Создает анонимный именованный канал (FIFO). 
  * **Решение проблемы Subshell:** Позволяет передавать вывод в цикл `while read` без запуска цикла в дочернем процессе, сохраняя значения всех переменных:
  ```bash
  total=0
  while read -r file; do
      total=$((total + 1))
  done < <(find . -type f)
  echo "Найдено файлов: $total" # Переменная НЕ обнулится!
  ```

## 6. Стандарты надежности в DevOps: Bash Strict Mode и trap

В боевых DevOps-скриптах (CI/CD pipelines, Docker-сборка, provisioning) скрипт обязан немедленно прерываться при возникновении сбоя, а не продолжать выполнять последующие разрушительные команды.

### 6.1. Unofficial Bash Strict Mode
Золотой стандарт в начале любого продакшн-скрипта:
```bash
set -euo pipefail
IFS=$'\n\t'
```
* **`set -e` (errexit):** Немедленно завершает скрипт, если любая команда возвращает ненулевой код ошибки (кроме условий `if`, `while`, `until`).
* **`set -u` (nounset):** Вызывает ошибку и останавливает скрипт при попытке прочитать необъявленную переменную. Защищает от фатальных опечаток вроде `rm -rf /tmp/$DIR_FOR_CLEAR/` при пустом `DIR_FOR_CLEAR`.
* **`set -o pipefail`:** Заставляет конвейер возвращать код ошибки, если упала **хотя бы одна** команда в цепочке (по умолчанию Bash возвращает код последней команды конвейера).
* **`set -x` (xtrace):** Режим трассировки. Печатает каждую выполняемую строчку с префиксом `+` — лучший инструмент для дебага сложных скриптов.

### 6.2. Механизм перехвата сигналов (`trap`)
Гарантирует освобождение системных ресурсов и удаление временных файлов даже при аварийном завершении или нажатии `Ctrl+C`:
```bash
# Создаем изолированную временную директорию
TEMP_DIR=$(mktemp -d)

cleanup() {
    rm -rf "$TEMP_DIR"
    echo "[INFO] Временная директория $TEMP_DIR очищена."
}

# Регистрируем вызов cleanup при любом завершении (EXIT), Ctrl+C (SIGINT) или kill (SIGTERM)
trap cleanup EXIT SIGINT SIGTERM
```

## 7. Парсинг опций командной строки через `getopts`

В реальных инструментах системного администрирования позиционные аргументы (`$1`, `$2`) вытесняются именованными ключами (`-f`, `-v`, `-d /path/`). Для этого в Bash встроен инструмент `getopts`:

```bash
#!/bin/bash

verbose=0
target_dir=""

# Двоеточие после буквы (d:) означает, что флаг требует аргумент
while getopts "vd:h" opt; do
    case "$opt" in
        v) verbose=1 ;;
        d) target_dir="$OPTARG" ;;
        h) 
            echo "Использование: $0 [-v] [-d директория]"
            exit 0
            ;;
        *) 
            echo "Неизвестный параметр. Используйте -h для справки."
            exit 1
            ;;
    esac
done

shift $((OPTIND - 1)) # Отсекает обработанные ключи, оставляя обычные аргументы
```
* `$OPTARG` автоматически сохраняет переданный параметру аргумент.
* `$OPTIND` содержит индекс следующего аргумента командной строки.

## 8. Массивы: Индексированные и Ассоциативные (Хэш-таблицы)

Начиная с версии Bash 4+, в язык встроена поддержка хэш-таблиц (key-value), что позволяет производить сложный анализ логов и метрик прямо в памяти.

### 8.1. Индексированные массивы (списки)
```bash
servers=("web01" "web02" "db01")
servers+=("cache01")       # Добавление элемента
echo "${servers[0]}"       # Доступ по индексу -> web01
echo "${servers[@]}"       # Все элементы -> web01 web02 db01 cache01
echo "${#servers[@]}"      # Размер массива -> 4
```

### 8.2. Ассоциативные массивы (словари / хэш-мапы)
Объявляются строго через ключевое слово `declare -A`:
```bash
declare -A ip_stats

# Подсчет количества уникальных обращений с каждого IP за O(1)
while read -r ip; do
    ((ip_stats["$ip"]++))
done < <(awk '{print $1}' /var/log/nginx/access.log)

# Итерация по ключам (${!array[@]})
for ip in "${!ip_stats[@]}"; do
    echo "Клиент $ip сделал ${ip_stats[$ip]} запросов"
done
```

```bash
2: 
3: if [ $# -ne 1 ]; then
4:     echo "Error: Wrong number of arguments."
5:     exit 1
6: fi
7: 
8: if ! [[ "$1" =~ /$ ]]; then
9:     echo "Error: Directory path must end with \"/\"."
10:     exit 1
11: fi
12: 
13: if [ ! -d "$1" ]; then
14:     echo "Error: Directory does not exists."
15:     exit 1
16: fi
17: 
18: start_time=$(date +%s.%N)
19: 
20: DIR="$( cd "$( dirname "${BASH_SOURCE[0]}" )" && pwd )"
21: source "$DIR/dirs.sh"
22: source "$DIR/exac.sh"
23: source "$DIR/files.sh"
24: 
25: find_dirs "$1"
26: find_files "$1"
27: find_exac "$1"
28: 
29: end_time=$(date +%s.%N)
30: echo "Script execution time (in seconds) = $(awk -v start="$start_time" -v end="$end_time" 'BEGIN { printf "%.2f\n", end - start }')"
```
* **Строка 8 (`if ! [[ "$1" =~ /$ ]]; then`):** Проверка, что путь заканчивается слэшем `/`.
* **Строка 13 (`if [ ! -d "$1" ]; then`):** Оператор `[ -d path ]` проверяет, существует ли директория на диске. Знак `!` означает логическое «НЕ».
* **Строка 18 и 29 (`date +%s.%N`):** Получение текущего Unix-времени в секундах с наносекундами (`%N`).
* **Строка 30 (`awk -v ... 'BEGIN { printf "%.2f\n", end - start }'`):** Поскольку Bash не умеет в вычисления с плавающей точкой в `$(( ... ))`, разница во времени рассчитывается через `awk` с точностью до 2 знаков после запятой (`%.2f`).

### Файл: `src/05/dirs.sh`
```bash
find_dirs() {
    local dirsinfo=$(find "$1" -type d 2>/dev/null | wc -l)
    echo "Total number of folders (including all nested ones) = $dirsinfo"
    echo "TOP 5 folders of maximum size arranged in descending order (path and size): "
    i=1
    du -h "$1" 2>/dev/null | sort -rh | head -5 | sed -e 's/K/KB/' -e 's/M/MB/' -e 's/G/GB/' | while read size path; do
        echo "$i - $path, $size"
        i=$((i + 1))
    done
}
```
* `find "$1" -type d | wc -l` — ищет все объекты типа директория (`-type d`) и подсчитывает строки через `wc -l`.
* `du -h "$1"` — вычисляет дисковое пространство в человекочитаемом формате (K, M, G).
* `sort -rh` — сортировка чисел с суффиксами единиц (`-h` = human-numeric-sort) в обратном порядке (`-r` = reverse, от большего к меньшему).
* `head -5` — отбирает первые 5 строк.

### Файл: `src/05/files.sh`
```bash
find_files () {
    files=$(find "$1" -type f 2>/dev/null | wc -l)
    echo "Total number of files = $files"
    echo "Number of:"
    conf=$(find "$1" -type f -iname "*.conf" 2>/dev/null | wc -l)
    echo "Configuration files (with the .conf extension) = $conf"
    text=$(find "$1" -type f -exec file {} + 2>/dev/null | grep -c "text") 
    echo "Text files = $text"
    exacutable=$(find "$1" -type f -executable 2>/dev/null | wc -l)
    echo "Executable files = $exacutable"
    logs=$(find "$1" -type f -iname "*.log" 2>/dev/null | wc -l)
    echo "Log files (with the extension .log) = $logs"
    archive=$(find "$1" -type f \( -name "*.tar" -o -name "*.gz" -o -name "*.bz2" -o -name "*.7z" -o -name "*.zip" -o -name "*.rar" -o -name "*.xz" \) 2>/dev/null | wc -l)
    echo "Archive files = $archive"
    symbolic=$(find "$1" -type l 2>/dev/null | wc -l)
    echo "Symbolic links = $symbolic"
}
```
* `-type f` — обычные файлы; `-type l` — символические ссылки.
* `-iname "*.conf"` — регистронезависимый поиск по расширению.
* `-executable` — проверяет права на исполнение файла.
* `\( -name "*.tar" -o -name "*.gz" ... \)` — круглые скобки группируют условия, а флаг `-o` выступает логическим ИЛИ.
* `find ... -exec file {} +` — передаёт найденные файлы пакетом в утилиту `file` для определения типа.

### Файл: `src/05/exac.sh`
```bash
find_exac() {
    echo "TOP 10 files of maximum size arranged in descending order (path, size and type): "
    i=1
    find "$1" -type f -exec du -h {} + 2>/dev/null | sort -rh | head -10 | sed -e 's/K/KB/' -e 's/M/MB/' -e 's/G/GB/' | while read size path; do
        echo "$i - $path, $size, ${path##*.}"
        i=$((i + 1))
    done
    echo "TOP 10 executable files of the maximum size arranged in descending order (path, size and MD5 hash of file): "
    i=1
    find "$1" -type f -executable -exec du -h {} + 2>/dev/null | sort -rh | head -10 | sed -e 's/K/KB/' -e 's/M/MB/' -e 's/G/GB/' | while read size path; do
        echo "$i - $path, $size, $(md5sum "$path" | awk '{print $1}')"
        i=$((i + 1))
    done
}
```
* `find "$1" -type f -exec du -h {} +` — измеряет размер каждого отдельного файла (в отличие от `du -h dir`, который суммирует папки).
* `${path##*.}` — извлечение расширения файла через срез строк Bash.
* `md5sum "$path" | awk '{print $1}'` — вычисляет MD5-хэш файла и забирает 1-й столбец (хэш-строку из 32 шестнадцатеричных символов).

# Часть III. Вопросы для подготовки к P2P-защите (Топ-10)

1. **Вопрос: Зачем вызывать `source` с конструкцией `DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"` вместо обычного `source ./check.sh`?**
   * *Ответ:* Если пользователь запустит скрипт из другой папки (например, находясь в домашнем каталоге: `bash /home/user/school21/.../src/01/main.sh`), относительный путь `./check.sh` будет искать файл в текущей рабочей директории терминала (`$PWD`) и упадет с ошибкой `No such file or directory`. Конструкция с `BASH_SOURCE` вычисляет реальное физическое расположение самого файла скрипта на диске, обеспечивая переносимость.

2. **Вопрос: Почему в проверке регулярных выражений в 01 написано `^[-+]?[0-9]+([.][0-9]+)?$`, а не просто `[0-9]+`?**
   * *Ответ:* Без якорей `^` и `$` регулярка `[0-9]+` будет искать любую цифру внутри строки (строка `user123` ошибочно посчитается числом). А квантификатор `([.][0-9]+)?` позволяет корректно классифицировать как целые (`42`), так и вещественные (`3.14`) числа любого знака, при этом требуя обязательного наличия цифр после точки (отсекая мусор вроде `12.`).

3. **Вопрос: Почему для расчета MASK в Ubuntu 24.04 не использован `ifconfig`?**
   * *Ответ:* Пакет `net-tools` (куда входит `ifconfig`) объявлен устаревшим и не поставляется по умолчанию в современных дистрибутивах Linux (включая Ubuntu 24.04 LTS). Современный стандарт де-факто — `iproute2` (`ip`). Мы извлекли префикс через `ip -o -4 addr` и преобразовали его стандартным модулем Python `ipaddress`.

4. **Вопрос: Почему в `data.sh` память выводится как `GB`, а не `Gb`?**
   * *Ответ:* В компьютерных науках строчная `b` означает биты (Gigabits), а прописная `B` — байты (Gigabytes). ТЗ прямо требует заглавные `GB` с точностью до трех знаков (`printf "%.3f GB"`). Ошибка в регистре приводит к несдаче тестов проверки.

5. **Вопрос: Зачем в `awk` для замера времени выполнения скрипта в 05 используется блок `BEGIN`?**
   * *Ответ:* Команда `awk 'BEGIN { ... }'` выполняется немедленно без ожидания входного потока из файлов или пайпов, что идеально подходит для выполнения математических операций с плавающей точкой над переданными переменными `-v start` и `-v end`.

6. **Вопрос: Чем отличается одиночный `[ ... ]` (test) от двойного `[[ ... ]]` (Bash extended test)?**
   * *Ответ:* 
     * `[` — это отдельная стандартная утилита POSIX (бинарник `/usr/bin/[` или встроенный аналог). В ней нет поддержки регулярных выражений `=~`, операторы `&&` и `||` внутри скобок запрещены (нужно писать `-a` и `-o`), а пустая переменная без кавычек (`[ $var = "text" ]`) приводит к синтаксической ошибке `unary operator expected`.
     * `[[` — это встроенное ключевое слово языка Bash. Оно поддерживает оператор регулярных выражений `=~`, логические связки `&&` и `||`, сопоставление по маскам `== *.*` и безопасно обрабатывает пустые переменные без обязательного оборачивания в кавычки.

7. **Вопрос: В чем опасность конвейера `command | while read` (Subshell problem) и как её избежать?**
   * *Ответ:* Конвейер `|` в Bash запускает правую часть в дочернем процессе (**подоболочке / subshell**). Любые переменные, счетчики или массивы, измененные внутри такого цикла, уничтожаются при завершении подоболочки. Для сохранения переменных используется подстановка процессов: `while read ...; done < <(command)`.

8. **Вопрос: Почему в `read -r` всегда рекомендуется указывать флаг `-r`?**
   * *Ответ:* Без флага `-r` (raw) утилита `read` воспринимает символ обратного слэша `\` как экранирование и удаляет его из ввода. При обработке системных путей файлов или логов это приводит к искажению строк (например, путь `\dir\file` будет прочитан как `dirfile`).

9. **Вопрос: Что такое `set -euo pipefail` и почему это пишут в начале DevOps-скриптов?**
   * *Ответ:* Это «Unofficial Bash Strict Mode». Он устраняет три главные причины тихих сбоев:
     * `-e` — прерывает скрипт при ошибке любой команды.
     * `-u` — прерывает скрипт при попытке использовать необъявленную переменную (защита от опечаток).
     * `-o pipefail` — конвейер возвращает ошибку, если упала *любая* команда в цепочке, а не только последняя.

10. **Вопрос: Как работает `2>/dev/null` и чем оно отличается от `2>&1`?**
    * *Ответ:*
      * `2>/dev/null` перенаправляет только поток ошибок (`stderr`, дескриптор 2) в псевдоустройство `/dev/null` (уничтожает ошибки), оставляя стандартный вывод `stdout` (дескриптор 1) видимым.
      * `2>&1` объединяет поток ошибок с потоком `stdout`, направляя их в одно и то же место (например, в файл или конвейер).
